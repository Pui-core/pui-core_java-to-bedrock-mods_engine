# ADR-0007: BDS への配置（dry-run・バックアップ・apply・rollback）

- 状態: 採用（実際の BDS では未検証）
- 日付: 2026-11-27
- 関連: #6, #1、前提は ADR-0006

## 背景

#6 の設計に「`world_resource_packs.json` / `world_behavior_packs.json` の安全な配置。dry-run 既定、停止中バックアップ、apply/rollback」がある。手で配置すると、次の事故が起きやすい。

- ほかのパックの項目を消す
- 同じパックを二重に登録する
- BDS の実行中にワールドを書き換える
- 戻し方が分からなくなる

## 決定

### CLI

| コマンド | 動作 |
|---|---|
| `modbridge bds-install <compile の出力> --bds DIR [--world NAME]` | 配置の計画を表示するだけ（dry-run、既定） |
| `modbridge bds-install <compile の出力> --bds DIR [--world NAME] --apply --confirm-stopped` | 配置する |
| `modbridge bds-rollback --bds DIR --backup ID --confirm-stopped` | バックアップから戻す |

ワールド名を省くと、`server.properties` の `level-name` を使う。

### 触る範囲

- `behavior_packs/modbridge-bp/` と `resource_packs/modbridge-rp/`（BDS のフォルダー直下。中身を毎回置き換える）
- `worlds/<ワールド>/world_behavior_packs.json` と `world_resource_packs.json` の、自分のパックの項目だけ。
  - 自分の項目とは、今回の UUID と、いま入っているパックの UUID（`--pack-id` を変えて作り直した場合の古いもの）。
  - ほかの項目と順序は残す。
  - 自分の項目は、既にあれば最初のものの位置で置き換え、残りは消す（やり直しても重複しない）。無ければ末尾に足す。
- ワールドの DB（`db/`）には触らない。`server.properties` も変えない（クライアントにリソースパックを強制する `texturepack-required` は、運用者が決める）

### 安全策

- **dry-run が既定**: `--apply` を付けない限り、何も変更しない。
- **配置と復旧の排他**: 同じ BDS フォルダーでは、配置と復旧のうち1件だけが書き込める。`.modbridge-bds.lock` を使って、DB の停止確認から操作完了まで排他する。競合した操作はパックやワールドを変更せずに終了する。空のファイルは同じロック先を使うために残し、プロセスが終了すればロックは解除される。
- **停止の確認**: `--confirm-stopped` の明示に加えて、`db/LOCK` があれば LevelDB のロックを取れるか確かめる。Windows では `MANIFEST-<番号>` と `<番号>.log` も、書き込みを共有しない読み取りモードで開く。開いている書き込みハンドルがあれば断る。読み取りは共有するため、配置中にハンドルを保持したままバックアップできる。RP/BP は BDS が共有するため、対象に加えて同じ `worlds/` にあるほかの実フォルダーの DB も確認する。DB がまだ無いワールドでは、明示だけを使う。[BDS の共有パック](https://learn.microsoft.com/ja-jp/minecraft/creator/documents/bedrockserver/getting-started?view=minecraft-bedrock-stable)
- **パックの組み合わせ**: BP の manifest にある RP への依存 UUID・版と、提供された RP のヘッダーを照合する。組が違えば dry-run と apply の両方で拒否する。apply は検査した組を使って配置する。Script API のモジュール依存を含む BP も同じ検査を通す。[Bedrock のパック manifest](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/addonsreference/packmanifest)
- **別ワールドの共有パック参照**: 同じ BDS フォルダー内で、複数のワールドに同じ UUID・版を登録できる。更新や rollback で既存の共有パックを置き換える前に、ほかのワールドの登録を確認する。使用中の版について、共有フォルダー内の別フォルダーか、そのワールドのパックフォルダーに全ファイルが一致するコピーが残らなければ、該当するワールド名とパックを表示して拒否する。apply は dry-run の確認に加えて、書き込みのロックを取った後にも確認する。
- **バックアップ**: 配置の前に、ワールドのフォルダー全体・自分のパックのフォルダー・2 つの JSON を `modbridge-backups/<UTC 時刻>/` に保存する。何があり、何が無かったかを `backup.json` に記録する。`db/LOCK` は保存しない（ロック中で読めない場合があり、LevelDB が作り直すため）。
- **入れ替え**: 復旧対象のパック、ワールド、JSON は、必要な複製をすべて用意してから入れ替える。途中で失敗した場合は、入れ替え済みの対象も操作前の状態に戻す。戻せなかった元のファイルやフォルダーは消さず、退避先の名前を表示する。入れ替え完了後に退避先の削除だけが失敗した場合は、復旧済みであることを表示する。
- **失敗時の復旧**: 配置の途中で失敗したら、配置で変えたもの（パックのフォルダーと 2 つの JSON）をバックアップから戻す。ワールドの DB はロック中で、配置では触らないので戻さない。復旧にも失敗したら、バックアップの ID を示して rollback を促す。
- **rollback**: ロックで停止を確かめてから、ワールドのフォルダーごと戻す。
  - ワールドのフォルダーを入れ替えるときは、対象ワールドのロックを放す。Windows では、開いているファイルを含むフォルダーを動かせないため。入れ替え後に対象のロックを確かめ、BDS が起動していたら知らせる。ほかのワールドのロックは復旧中も保持する。
  - 戻す前にあった `db/LOCK` は作り直す。
  - バックアップは、削除や入れ替えを始める前にすべて検査する。
    - ID の形式（`yyyyMMddTHHmmssZ`）
    - `backup.json` のワールド名（下の規則）
    - 対象が、そのワールド名から決まる 3 つ（ワールド・BP・RP のフォルダー）と完全に一致すること
    - 値が真偽値であること
    - 「あった」とされる対象が、バックアップの中に実際にあること
    - ワールドが「あった」こと（配置はワールドがあるときにしか行わないので、正しいバックアップでは必ずそうなる）

    書き換えられた `backup.json` で、ほかのワールドや `worlds/` を消さないため。
- **入力の検査**: `.mcpack` は上限付きで展開する。エントリー名は ZIP Slip の検査（ADR-0003）を通す。`manifest.json` の UUID・版・モジュールの種類も確かめる。ワールド名には、パスの区切り文字・制御文字、`.`・`..`、先頭・末尾の `.` や空白を使えない。解決したパスが `worlds/` の直下であることも確かめる。
- **配置・復旧先の検査**: BDS のルートと、操作するパック・ワールド・バックアップへの経路にあるシンボリックリンク、Windows のジャンクション、特殊ファイルを拒否する。配置前のバックアップと復旧のコピーも、リンクをたどらずに中断する。

## 実測（2026-11-27、BDS 本体は使わない）

- 単体テスト 79 件が成功した（`BdsInstallerTest` 10 件を含む）。BDS と同じフォルダー構成を作って、次を確かめた。
  - dry-run は何も変更しない
  - 明示が無いと配置しない
  - DB のロックを持たれていると配置しない
  - ほかのパックの項目を残し、やり直しても重複せず、古い中身を残さない
  - ワールドの DB に触らない
  - rollback で配置の前と同じになる
  - 途中の失敗で元に戻る
  - 不正なワールド名（`.`・`..`・空白など）・バックアップ ID を拒否する
  - 書き換えられた `backup.json`（対象の追加、`worlds/`、真偽値でない値、不正なワールド名）では何も消さない
  - パック ID を変えて作り直しても、古い項目を残さず、元の位置で置き換える
- CLI で、スパイクの `mods/` から作ったアドオンを、試験用の BDS フォルダーに dry-run → apply → rollback した。
  - BP には、アイテム・ブロック・レシピ 2 つのファイルが入った。
  - `world_behavior_packs.json` に、自分の項目が 1 つ入った。

## DB の停止確認（2026-11-28）

- Minecraft for Windows 26.65 の隔離ローカルワールドでは、利用中にも `db/LOCK` が無かった。DB の書き込みファイルを使う検査では、ワールドを開いている間は拒否し、保存して閉じると通過した。閉じた DB のコピーを使って配置・復旧し、復旧後のワールドのファイルが配置前と一致した。
- Linux では WSL の ext4 上で別プロセスに LevelDB 1.23 を開かせると、CLI の配置と復旧はどちらもロックを検出して拒否された。DB を閉じた後は両方が成功した。

## 未検証・既知の制約

- **実際の BDS で、配置したアドオンが読み込まれるかは未確認**。BDS の起動には、Minecraft の EULA とプライバシーポリシーへの同意が要る。これは owner の判断を待っている。
- Windows・Linux の公式 BDS が使うワールドを対象にした停止確認は未実施。
- バックアップはワールド全体を複製するので、大きなワールドでは時間と容量がかかる。古いバックアップは自動では消さない。
- Windows では、フォルダーの置き換えは原子的ではない（2 回の移動の間に、一瞬だけ対象が無い）。
- 複製では、ファイルの属性（権限・更新時刻）を保たない。
- BDS が起動した直後で、まだ `db/LOCK` を開いていない瞬間は、ロックで検知できない（`--confirm-stopped` の明示に頼る）。
- rollback では、バックアップの後に BDS で遊んだ分のワールドの変化も戻る（バックアップ時点に戻す）。
