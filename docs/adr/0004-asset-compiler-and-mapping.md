# ADR-0004: 共通素材コンパイラ・リソースパック生成・対応表

- 状態: 採用（Minecraft for Windows 26.65 のローカルワールドで描画確認済み）
- 日付: 2026-11-27
- 関連: #4, #1、前提は ADR-0003

## 背景

Mode B（BDS で Bedrock ネイティブに動かす）では、Java の MOD の素材を Bedrock のリソースパックに変換する必要がある。Mode A では Hydraulic が自動で変換するが、その結果は制御できない。たとえば、素材の無い定義はスキップされる（ADR-0003 の実測）。#4 では、変換を自前で行い、何を変換し、何を変換できなかったかを対応表に残す。

既存の変換器の流用も検討した。

| 候補 | ライセンス | 判断 |
|---|---|---|
| Rainbow | GPL-3.0 | 使わない。MIT を想定する本体に組み込めない（ライセンスの最終判断は owner） |
| PackConverter（GeyserMC、Hydraulic が使用） | MIT | 今回は使わない。Mode A のための変換で、Java と同じ翻訳キーを使うなど、Mode B と前提が違う。将来の比較対象にする |

## 決定

### 構成（`dev.puicore.modbridge.core.compile`）

| クラス | 役割 |
|---|---|
| `ModelResolver` | Java のモデル・blockstate・アイテム定義を、単純な形に解決する |
| `Png` | PNG のヘッダーで縦横と画素数を確かめてから、必ず展開して壊れていないかを確かめ、透過の種類を判定する |
| `BedrockIds` | Java の識別子から、Bedrock の識別子・テクスチャ短縮名・パック内のパスを作る |
| `PackCompiler` | IR と JAR から、リソースパック（.mcpack）と対応表（mapping.json）を作る |
| `PackPublisher` | キャッシュと、旧成果物を守る公開 |

CLI は `modbridge compile <jar|dir>... --out DIR [--runtime FILE] [--cache DIR] [--pack-name NAME] [--pack-id ID]`。

### 対応する形（初期は単純なものだけ）

| 種類 | 対応 | 非対応（理由を付けて SKIPPED にする） |
|---|---|---|
| アイテム | `items/*.json` の `minecraft:model` → `item/generated`・`item/handheld` を親に持つ平面アイテム（`layer0`）。layer1 以降は重ねず、PARTIAL にする | `select`・`condition` などの分岐、`tints`、それ以外の親 |
| ブロック | 状態を持たない blockstate（変種のキーが `""` だけ）で回転の無いもの → `cube_all`・`cube_column`・`cube_bottom_top`・`cube` | multipart、状態を持つ変種（`facing=north` だけの場合も含む）、`x`・`y`・`uvlock`、`elements` を持つ独自の形、それ以外の親 |
| ブロックアイテム | 同じ ID のブロックを変換できたら、見た目はブロックから作る | 同じ ID のブロックが SKIPPED のとき |
| テクスチャ | MOD の名前空間の PNG（縦横 4096 px まで、かつ 2048x2048 相当の画素数まで） | バニラのテクスチャの参照、アニメーション（`.png.mcmeta`）、壊れた PNG、画素数が上限を超える PNG |
| 名前 | Java の言語ファイルのうち、Bedrock にある言語だけ。ブロックのキーは `tile.<id>.name`。アイテムは資料で `item.<id>.name` と `item.<id>` が混在するので、実機で確かめるまで両方を出す | Bedrock に無い言語 |

- **透過**: ブロックの面のテクスチャのうち最も透過の強いものから、`render` を `opaque` / `alpha_test`（完全な透明がある） / `blend`（半透明がある）に決めて、対応表に記録する。Mode B の `material_instances` で使う（#6）。
- **parent・texture 変数**: 親を最大 16 段たどり、子の指定を優先する。`#var` の参照も解決する。
- **読み込み**: JAR は 2 回開く。1 回目はテキストだけを読んでモデルを解決し、2 回目は解決できたモデルが参照する PNG だけを読む。参照されない大きな PNG で失敗しないためと、メモリを節約するため。どちらの回も SHA-256 を IR と照合する。
- **テクスチャの登録**: 定義の変換が成功してから登録する。一部の面だけ読めたブロックのテクスチャは、パックに入れない。別々の JAR が同じテクスチャ ID で違う画像を持っていたら、`TEXTURE_CONFLICT`（ERROR）にする。

### 識別子と衝突

- Bedrock の識別子は `[a-z0-9_]` だけを使い、それ以外の文字は `_` にする（例: `ns:a/b` → `ns:a_b`）。
- 変換で別々の Java 識別子が同じ Bedrock 識別子になったら `ID_COLLISION`（ERROR）にし、何も作らない。テクスチャの短縮名の衝突も `TEXTURE_ID_COLLISION`（ERROR）にする。
- 同じ Java 識別子のアイテムとブロックは、ブロックアイテムとして衝突にしない。

### パック

- `manifest.json`: `format_version` 2。ヘッダーとモジュールの UUID は、パック ID（`--pack-id`、既定 `modbridge`）から決める（UUID v3）。同じパック ID なら、内容が変わっても同じパックとして扱われる。
- **版**: 内容ハッシュの先頭 28 ビットを上位・下位の 14 ビットに分け、RP・BP ともに `[1, 上位14ビット, 下位14ビット]` にする。成分の最大値は 16383。Bedrock は UUID と版が同じパックを取得済みとして使い回すので、内容ハッシュから版を決める。版は単調増加しない。
- `min_engine_version` はブロックの書式に合わせて `[1, 21, 80]` を指定する（ADR-0006）。
- **決定性**: ZIP のエントリーは名前順にし、時刻は 1980-01-01 00:00 に固定する。JSON のキーは順序を固定する。同じ JDK なら、同じ入力・設定から同じバイト列になる（テストで確認）。JDK によって圧縮の結果が変わる可能性はある。
- **上限**: パック 256 MiB、テクスチャ 16384 個。

### 対応表（`mapping.json`、`modbridge.mapping` 版 1）

定義ごとに、Java の識別子、Bedrock の識別子、状態（GENERATED / PARTIAL / SKIPPED）、面とテクスチャの短縮名、`render`、注記を記録する。テクスチャごとに、短縮名、パス、縦横、透過の種類を記録する。パックの UUID・版・内容のハッシュ、生成時の診断も記録する。

### fail closed

- IR に ERROR 診断があれば `IR_HAS_ERRORS` にして、何も作らない。
- JAR は開き直すたびに、IR に記録した SHA-256 と照合する。解析の後で変わっていたら `INPUT_CHANGED`（ERROR）にする。
- コードでだけ登録された定義（`RUNTIME_REGISTRY`）と、Mode B の計画が対応不可の定義は、SKIPPED にする。
- 非対応の形は WARN を出して SKIPPED にし、パックには入れない。変換は続ける。

### キャッシュ

- 鍵は、生成器の版、対象バージョン、設定（パック名・ID）、アダプター（まだ無い。#7）、IR の JSON の SHA-256 である。IR には入力 JAR の SHA-256、依存、実行時レジストリが入るので、どれかが変われば鍵も変わる。
- キャッシュを使う場合も `compile` は解析・生成の診断と RP/BP の変換結果を表示する。`mapping.json` に生成時の診断を保存する変更で、鍵の生成器の版を `pack-compiler/4` に上げた。
- キャッシュには、ファイルごとの SHA-256 を一緒に保存する。次のどれかに当たれば使わずに作り直す。
  - SHA-256 が合わない
  - パックと対応表の 2 つが揃っていない
  - 行が重複している、または余分な行がある
  - 対応表に記録した内容のハッシュが、パックの中身と一致しない
  - 対応表から生成時の診断を復元できない

### 公開

- 一時フォルダーにすべて書いてから、出力フォルダーと入れ替える。旧フォルダーは入れ替えが済んでから消す。入れ替えに失敗したら、旧フォルダーを元に戻す。元に戻すのにも失敗したら、旧フォルダーは消さずに残し、その名前をメッセージで示す。生成に失敗した場合は、出力フォルダーに触らない。
- 出力フォルダーは、空か、印（`.modbridge-pack`）のあるフォルダーに限る。ほかの用途のフォルダーを消さないため。ルート、現在のフォルダーとその親、シンボリックリンクは出力先にできない。
- Windows では、フォルダーの入れ替えは原子的ではない（2 回の移動の間に一瞬だけ出力フォルダーが無い）。

## 実測（2026-11-27）

- 単体テスト 57 件が成功（`./gradlew build` の集計）。コンパイラの対象は次のとおり。
  - fixture 相当の変換（アイテム・ブロック・ブロックアイテム・言語 2 つ）
  - 同じ入力から同じバイト列（入力の順序にもよらない）
  - 内容が変わったら版が変わり、UUID は変わらない
  - キャッシュの鍵の変化（入力・設定）と、壊れたキャッシュ（チェックサム違い・欠け・重複行・パックと対応表の不一致）を使わないこと
  - ID の衝突、IR の ERROR、解析後の JAR の変化で何も作らないこと
  - 非対応の形（向き・独自の形・アニメーション）と透過の判定（半透明・切り抜き）
  - 大きすぎる PNG を展開しないことと、壊れた PNG を使わないこと
  - 状態を持つ blockstate（変種が 1 つでも）を使わないこと
  - 参照されない大きな PNG を読まないこと
  - 同じテクスチャ ID で違う画像を持つ JAR を拒否すること
  - 現在のフォルダーに公開しないこと
  - 公開の失敗時に旧成果物が残ることと、印の無いフォルダーを消さないこと
- スパイク環境の `mods/` 一式と実行時レジストリで `modbridge compile` を実行した。
  - 結果は GENERATED 3（`test_ingot`、`test_block` のブロックとアイテム）、SKIPPED 1（`code_only_marker`、素材なし）。パックは 2.3 KB だった。
  - 同じ条件の 2 回目は、キャッシュを使った。
- Hydraulic が同じ fixture から作ったパック（Mode A 用）と比べた。
  - atlas の構造は同じだった。
  - 言語キーは違った。Hydraulic は Java と同じキー（`item.pmb_fixture.test_ingot`）を使う。Geyser は Java の翻訳キーで名前を送るためである。このパックは Mode B（BDS）用なので、Bedrock のネイティブなキーにしている。

### Minecraft for Windows 26.65 のローカルワールド

実機で、従来の版 `1.0.199669562` の RP と `1.0.2362806` の BP は検証用のパック一覧に出なかった。同じ素材で版を `1.0.0` にした比較用パックは、標準と開発用のパックフォルダーの両方で表示された。新しい方式で生成した RP `1.12186.14138` と BP `1.5252.972` が表示され、新規のローカルワールドに両方が適用されたことをワールドのパック設定から確認した。境界値 `1.16383.16383` の比較用 BP も一覧に出た。検証には生成済みの RP/BP を開発パックフォルダーへ展開して使った。

| 項目 | 観測結果 |
| --- | --- |
| 6 面の向き | `pmb_assets:face_cube` の北・東・上が赤・橙・青、南・西・下が黄・緑・紫。反対側からも撮影して照合した |
| 切り抜きと半透明 | `cutout_cube` の穴は背後の壁をその色のまま表示した。`blend_cube` の中央は明るい壁と暗い壁で異なる青の合成色になった |
| 言語 | `give @s pmb_assets:face_cube` で日本語の「6面色分けブロック」を表示した |
| 非対応 | 状態依存の `unsupported_facing` は生成時に `MODEL_UNSUPPORTED` と `SKIPPED` になり、ワールドのブロックとして指定できなかった |
| キャッシュ | 同じ入力とキャッシュフォルダーで旧版を再利用せず、修正版の2回目はキャッシュから同じバイト列を出力した。RP・BP の UUID は維持された |

入力 `asset-probe.jar` の SHA-256 は `ec19d0709e091f2a5a9680038ac87a50649ed2133188bd523bddbce0d0ab0b5c`。修正版 `modbridge.mcaddon` の SHA-256 は `91a2ed205844de7c6c30690f4221e245c1a6773583447c895ae78e003eaf5bbb`。検証時の画像は `bedrock-v3-faces-ne.png`、`bedrock-v3-faces-sw.png`、`bedrock-v3-opacity.png`、`bedrock-v3-opacity-dark.png`。

## 未検証・既知の制約

- 最小対象版 1.21.80 での実測と BDS のサーバー動作は未検証。
- 立方体以外の形、状態ごとの見た目、アニメーション、色付け、バニラのテクスチャの参照は非対応（v0.5.0 以降）。
- パックの版は単調増加ではない。Bedrock が版の大小を比べる場面（更新の判定など）での挙動は未確認。
